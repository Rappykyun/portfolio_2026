# Domain Docs

Before exploring, read:

- `CONTEXT.md` at the repo root, if it exists
- `docs/adr/`, reading ADRs relevant to the area being changed

If these files do not exist, proceed silently. Create them lazily when domain terms or architectural decisions need to be recorded.

Use the glossary’s vocabulary in issue titles, proposals, and tests. Flag conflicts with existing ADRs instead of silently overriding them.
